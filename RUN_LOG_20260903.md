## 09-07 ~10:00-11:00 — Goal 3 deployment: found + fixed a real cross-project regression

User approved proceeding with both Goal-3 items (deploy `predict_dg.py`, package the
classification/ranking reformulation). Smoke-tested `predict_dg.py` first (20 real pairs
sampled from `cross_round10_dft_products.csv`) before calling it "deployed" — good thing:
it was completely broken for new pairs.

**Bug found**: `combined: 0 rows` then a downstream KeyError. Root cause: the 09-06 BDE
featurize rebuild computes local g-xTB-level bond descriptors but never recomputes the
whole-molecule g-xTB Gibbs energy (`G_gxtb`, only the GFN2-level `G_ald_xtb`->`G_xtb`) --
never needed it for BDE's own bond-energy target. `load_round()`'s aldehyde-descriptor
merge used `donor_G_gxtb`/`acceptor_G_gxtb` as its "did this row match the library"
coverage sentinel, so it silently zeroed every row even though the real canonical-SMILES
merge had succeeded (confirmed manually: all 5 sampled donor SMILES canon-matched fine).
Verified via the raw `chunk_0000/aldehydes.csv` worker output (no G_gxtb column exists at
all) vs the pre-rebuild 42k partial-library backup (G_gxtb 42332/42335, 99.99% -- so this
is a real regression from this week's rebuild, not a pre-existing gap). Current full
library: G_gxtb populated 2,718/209,526 (1.3%, only the rows backfilled from the old
partial file).

**Fix** (commit `c520acf`): swapped the sentinel to `donor_xtb_HOMO`/`acceptor_xtb_HOMO`
(99.9%+ populated by any real match, architecturally unrelated to the G_gxtb gap) in both
`assemble_cross_training_table_combined.py::load_round` and the legacy sibling in
`assemble_cross_training_table.py`. `donor_G_gxtb`/`acceptor_G_gxtb` are 2 of the 260
frozen champion features -- they now correctly fall through to the existing downstream
median-impute for new pairs (same fallback every other optional feature already uses),
rather than causing every row to be dropped. Re-smoke-tested: all 20 rows now survive,
full pipeline runs to completion, predictions look sane (mostly single-digit to
low-double-digit kcal, in the same range as `dG_gxtb_kcal`) except 2/20 wild outliers
(549, 753 kcal) that the model's own `ens_member_sigma` correctly flags as huge (153,
207) -- i.e. the uncertainty column is doing its job identifying out-of-distribution
structures (complex fluorinated heterocycles), not a new bug.

**Not done**: actually recomputing G_gxtb for the ~207k affected aldehydes (geometries
are preserved, so a Gibbs-correction rerun not a full reopt, but still real compute for

**Scope check confirmed**: this bug is specific to `predict_dg.py`'s NEW-pair prediction
