## 1. 2026-07-13 至 2026-07-14 — 接入真实数据集 + homo 冠军打包

1. **拉取 GitHub 真实 `candidates_v3` 数据集**（2M 无向 / 4M 有向对），用免 root 的
   `git-lfs` 静态二进制安装。它自带分子级不相交的 80/10/10 训练/验证/测试划分
   （`inchikey_split_map.parquet`）。
2. **发现早期自定义采样的 split 一致性缺陷**：round-1 有 184/598（31%）的对中 donor 与
   acceptor 落在**不同的 split**，因为自定义生成器是从 aldehyde 池里自由配对的。决策：
   round 3 起直接从 `candidates_v3` 自带的对列表里采样。
3. **搭建并运行产物 BDE 计算**（`calc_bde_gxtb_product_cross.py`），跑了 round 1-2。在
   n≈598 时，donor/acceptor BDE 与产物 BDE 都**看不出可测信号** —— homo 侧真实的 BDE
   增益（1.525→1.503）在这个样本量下被 ~2.7 kcal 的残差噪声淹没；杠杆是数据量，不是
   更多特征。
4. **关闭 ENSEMBLE72 homo 冠军打包缺口**（此前两次被推迟）：新增
   `src/benzoin_dG/_ensemble72_inference.py` 适配器 + `predict_dG_champion()`。用
   `envs/bde_lite` 子进程桥（`_ensemble72_predict_subprocess.py`）持久化解决了 numpy≥2
   的 `RandomState` 反序列化问题。在苯甲醛上验证：预测 3.616 对真实 DFT 标签 3.591。
5. **Round 3 采样**（`sample_round3_from_candidates_v3.py`）：4,200 对 / 8,400 有向行，
   直接从 `candidates_v3` 的 train-split 块里采样，类别均衡。
6. **发现并修复一处静默 chunk 失败 bug**：`submit_cb_featurize_array.sh` 结尾的
   `echo ... exit=${PIPESTATUS[0]}` 让 SLURM 把每个 chunk 都记成 COMPLETED，即使 Python
   进程硬失败。round-3 有 16/84 个 chunk 静默丢了约 1,600 行。修复为捕获
   `RC=${PIPESTATUS[0]}` 并 `exit "$RC"`。
